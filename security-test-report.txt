Coverage of the assignment requirements

Covered
- Valid input: level indexes 0, 1, and 2.
- Missing input: build_level() with no argument.
- Empty input: an empty string passed as a level index.
- Incorrect type: text, None, a text airplane position, a bad raindrop, and bad platform values.
- Negative values: a negative level index is documented, and negative airplane coordinates are clamped.
- Extremely large values: level index 1000000000, and airplane coordinates of one billion and of ten times the screen height.
- Unexpected values: None as the keyboard, None as the player in the hazard check.
- Level progression: source starts at 0, increases by one beside the goal test, and the airplane does not start on the goal.
- Scores: the three game files have no score.
- Lives: the constant is 3 and the source stops at 0. The below-zero check repeats that rule inside the test; it does not run the game loop.
- Win condition: overlapping the goal is the progress signal, and won = True appears once. The running loop is not executed.
- Invalid input and error handling: the four error tests, plus the rejected level values.
- Sensitive information: exception text and the listed project files are checked for a home path, a password assignment, an API key, and a private key.
- Browser output: level names stay out of the HTML, document.write and eval are absent, and lives go through font rendering.
- Production configuration: the debug panel starts hidden, the frame does not request the camera, microphone, or location, a Content Security Policy tag exists, and requirements.txt does not add a web framework.

Not fully covered
- The game window loop in main() is never started. No test plays a frame, presses Space or R, or proves the running game survives bad keyboard input.
- Lives and the win flag are checked by reading main.py and by copying the life rule into the test. A hit, a negative life count, and a win are not produced by calling the loop.
- Empty keyboard input, meaning no key held down, is not given to Player.update as a normal case.
- The browser tests read index.html. They do not open the page in a browser.
- The configuration tests do not check the remote pythons.js integrity attribute, and they do not check that the documented server command binds to 127.0.0.1. They only check that a Content Security Policy tag exists, not whether that policy is strict.

No test failed. The gaps above are missing checks, not failures.
